# Перенос доработок PrimeDoor в Doorium

Референс — репозиторий `Xatab4ik13/doorway-dynamics`. Переносим только пункты ТЗ, ничего сверх. Прайс-лист и цены в смете не трогаем.

## 1. Миграция БД

Новый файл `backend/migrations/2026-08_comments_and_extras.sql`:

- `request_comments`: `id`, `request_id` (FK → requests, ON DELETE CASCADE), `author_id`, `author_name`, `author_role`, `stage` ('measurement' | 'installation' | 'general'), `text`, `created_at timestamptz`, `updated_at timestamptz`, `edited_at timestamptz`, `is_deleted boolean default false`; индекс по `(request_id, created_at)`.
- Разовый перенос непустых `requests.notes` в ленту комментариев (как в PrimeDoor).
- `requests`: `entrance_panels INTEGER`, `baseboard_meters NUMERIC(10,2)`, `portals INTEGER`, `parent_request_id UUID`.
- Приведение `created_at`, `updated_at`, `closed_at`, `agreed_date`-независимых полей к `timestamptz` (только если сейчас `timestamp`), с интерпретацией существующих значений как UTC.
- `GRANT SELECT, INSERT, UPDATE, DELETE ON public.request_comments` пользователю приложения.

`child_request_ids` отдельной колонкой не заводим — связи хватает через `parent_request_id` (так же в PrimeDoor); дочерние заявки выбираются запросом.

Команды миграции и деплоя на VPS выдам после реализации.

## 2. Комментарии

- Backend: `GET /api/requests/:id/comments`, `POST /api/requests/:id/comments`, `PUT /api/comments/:id`, `DELETE /api/comments/:id`.
- Доступ: все роли, включая партнёров (партнёр — только по своим заявкам), могут читать и писать.
- Правка/удаление: свои — автору (мягкое удаление, `is_deleted`, в ленте «комментарий удалён»); admin/manager — любые, с жёстким удалением из БД.
- UI: лента комментариев в `RequestDetailModal` (отдельная вкладка/блок), с автором, ролью, датой ДД.ММ.ГГГГ, пометкой «изменено».
- При клонировании заявки (замер → монтаж, повтор, рекламация) комментарии копируются из родителя.

## 3. Файлы по этапам

- У каждого элемента `photos` есть `stage`.
- Создание замера → `measurement`; создание монтажа/рекламации → `installation`.
- Клонирование: файлы родителя копируются с сохранением исходного `stage`.
- В карточке — два блока: «Файлы замера» и «Файлы монтажа»; файлы без `stage` попадают в «Файлы замера».
- Догрузка в существующую заявку: замерщик → `measurement`, монтажник → `installation`, admin/manager/партнёр → по типу заявки.

## 4. Новые поля заявки

`entrance_panels` (входные панели), `baseboard_meters` (плинтус, м/п), `portals` (порталы) — в форму создания/редактирования монтажа, в партнёрскую форму, в карточку заявки, в клонирование и в экспорт списка заявок (там, где уже выводятся межкомнатные/входные/перегородки).

## 5. Сохранённые сметы

- `estimates`: добавить `client_phone`, `address` (уже есть `client_address` — используем его), `city` — недостающие поля добавляются миграцией.
- Компонент `SavedEstimates` + страницы для admin / manager / installer, ссылки в сайдбаре и мобильной навигации.
- Список с поиском по ФИО, телефону, адресу, номеру сметы, городу.
- Клик по смете → калькулятор в режиме редактирования → сохранение обратно (`PUT /api/estimates/:id`).

## 6. Календарь

- Скрывать статусы: `closed`, `cancelled`, `client_refused`, `pending`, `measurement_done`.
- Показывать только заявки с `agreed_date`; загрузка через `scheduled=1` (backend отдаёт такие заявки без лимита), поэтому рекламации с датой тоже видны.

## 7. Отчёты и таймзона

- Константа `REPORT_TIMEZONE = 'Europe/Moscow'`, все группировки по датам через `AT TIME ZONE 'Europe/Moscow'`.
- Ручное закрытие заявки: `closed_at` = 12:00 UTC выбранного дня.
- Статистика дашборда: убрать декартовы произведения (агрегации отдельными запросами), кумулятивная воронка, корректная динамика по неделям.

## 8. Адреса / DaData

Использовать полный адрес из подсказки (регион + город/населённый пункт), не подставлять «Москва». Город определять по `region` подсказки: Москва или Московская область.

## 9. Автостатусы

При установке `agreed_date` менеджером/админом заявка переходит в `date_agreed`; если статус изменён вручную в том же запросе — автопереход не применяется.

## 10. SMS

SMS уходят только ролям `measurer` и `installer` (переменная `SMS_ROLES`), остальным — только Telegram.

## 11. Повтор заявки

Кнопка «Повторить заявку» в карточке: создаёт новую заявку с данными клиента, адресом, городом, доп. контактом, новыми полями монтажа, с `parent_request_id`, копированием файлов (с их `stage`) и комментариев.

## Технические замечания

- В Doorium нет статуса `installer_assigned` (есть в PrimeDoor) — новые статусы не вводим, автопереходы адаптируем под текущий набор Doorium.
- Backend-миграции запускаются вручную на VPS через `psql`; в конце дам точные команды `git pull` + миграция + `systemctl restart doorium-api`.
- Фронтенд-типы `ApiRequest` и хуки обновляются под новые поля.
